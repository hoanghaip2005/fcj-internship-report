# Reflection on AWS Cloud and AI Day Hanoi

### 1. Event information

- **Date:** September 29, 2026.
- **Schedule:** 07:30–17:00, Vietnam time; keynote at 09:00.
- **Main venue:** JW Marriott Hotel Hanoi.
- **Organizer:** Amazon Web Services (AWS).
- **Format:** In-person sessions, workshops and technology exhibitions.

The agenda includes parallel sessions and an HCMC Watch Party entry. The badge identifies the program; it does not establish the attendee's physical location or completed sessions.

### 2. Learning objectives

My internship learning goal is to connect AWS infrastructure, data and application development. The event topics provide a useful framework for understanding agentic AI, data foundations, modernization and developer tools. I focus on the problem each technology solves, the prerequisites for deployment and the evidence needed to evaluate results.

### 3. Program topics and learning reflections

#### Keynote and practical problem solving

**What does it take to solve problems everyone says are impossible? — KEY001** is scheduled at 09:00. The program overview emphasizes enabling builders through agentic systems, workload modernization and security. My takeaway is to start with a clear user need, appropriate data and measurable results. A bounded, testable workflow is a practical internship objective.

#### Production agents

**From Demo to Deployment: Solving Agentic AI's Toughest Challenges — AIM201**, listing **Katalon and AWS**, is scheduled at 11:00 in Grand Ballroom 1. The topic prompts questions about data correctness, tool permissions, error handling and execution cost. In a proposed application, a model's statement that an update succeeded must be checked against the actual API result. Application code must enforce identity, authorization and parameter validation.

#### AI-ready data

**Build and AI-ready data foundation — ANT202**, listing **AWS**, is scheduled at 11:00 in Ho Tay. My related study takeaway is to define document versions, freshness, permissions and business meaning before adding AI. For a RAG experiment, evaluate retrieval and answer generation separately to locate errors in data selection or unsupported generated claims.

#### Software development and engineering platforms

The catalogue includes **Building software like never before with agentic AI — DVT203** from AWS, **Platform Engineering at Scale: Internal Developer Platform on EKS — DEV205** listing VPBank, and **Don't use a Ferrari to Get Phở — DEV303** listing Cloud Kinetics. Without detailed presentation material, the last title does not establish a specific technical recommendation.

My reflection is that developer productivity also depends on reproducible environments, clear requirements, testing and observable deployments. EKS is a subject for further learning after container, networking and authorization fundamentals. Platform choices should reflect the workload and the team's operational capacity.

#### Migration and modernization

**Migration at Scale with Agentic AI: AWS Transform and Beyond — AIM302**, listing AWS, is scheduled at 11:00 in Grand Ballroom 2. I connect this topic to dependency discovery, testing, target preparation and recovery planning. Generated code and configurations require review against the actual system before adoption.

#### Community and hands-on activities

The program advertises an Expo, Startup Zone, Developer Community Zone, Workshops and 8-Bit Agents Activation. The catalogue also lists **Amazon Quick Play & Build: Create Your AI Assistant, Compete, Win — AIM103**, from AWS. A useful learning approach is to record each demonstration's problem and components, then reproduce a manageable part. No personal workshop completion, deployment or prize is claimed here.

### 4. Personal lessons

AWS fundamentals support all these topics. I need to understand resource access, networking and storage before adopting more complex tools. Experiments should define inputs, expected outputs and failure cases. Tool selection should balance user value, cost and operational effort.

### 5. Planned internship applications

| Area | Proposed work | Verification |
|---|---|---|
| AWS labs | Document access flows and permissions | Explain each resource's role |
| DropIt | Define document metadata and investigate read-only retrieval | Correct source, version and sharing scope |
| FitJoy | Use explicit requirements and tests with AI coding assistance | Agreed functionality; no AWS deployment claim |
| AI prototype | Include answerable and out-of-scope questions | Detect unsupported or incorrect answers |
| Documentation | Record decisions, limitations and checks | Reproduce the main workflow |

These are proposed learning activities, not completed results.

### 6. Conclusion

The program connects Cloud infrastructure, data and application development. My main takeaway is to place new technology within a process of clear requirements, authorization and result verification. I will prioritize AWS fundamentals and one bounded experiment before expanding scope.
